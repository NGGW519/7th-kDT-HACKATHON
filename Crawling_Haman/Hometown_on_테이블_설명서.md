# Hometown_on 데이터베이스 테이블 설명서

## 📋 개요

이 문서는 함안군 귀향자 정착 지원 플랫폼 **Hometown_on**의 PostgreSQL(PostGIS + pgvector) 데이터베이스 스키마에 대한 상세 설명서입니다. 총 34개의 테이블로 구성되어 있으며, 사용자 관리부터 AI 기반 검색까지 모든 서비스 기능을 지원합니다.

## 🗂️ 테이블 분류 및 구조

### 🔹 1. 사용자 관리 (User Management)

#### `users` - 기본 사용자 계정
```sql
CREATE TABLE users (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  email VARCHAR(255) CONSTRAINT uq_users_email UNIQUE,
  password_hash VARCHAR(255),
  phone VARCHAR(30),
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
CREATE TRIGGER trg_users_updated_at BEFORE UPDATE ON users
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```
- **역할**: 플랫폼의 기본 사용자 계정 정보
- **핵심 필드**: 이메일, 비밀번호 해시, 전화번호

#### `user_profiles` - 사용자 상세 프로필
```sql
CREATE TABLE user_profiles (
  user_id BIGINT PRIMARY KEY REFERENCES users(id),
  display_name VARCHAR(80),
  profile_image VARCHAR(500),
  birth_year SMALLINT,
  gender VARCHAR(6) CONSTRAINT ck_user_profiles_gender CHECK (gender IN ('male','female','other')),
  home_region VARCHAR(120),      -- 고향/귀향 지역(예: 경남 함안군)
  target_region VARCHAR(120),    -- 정착 희망 지역
  preferences JSONB,             -- 관심분야/선호 카테고리/가용시간 등
  bio TEXT,
  mentor_available BOOLEAN DEFAULT false,
  mentor_hourly_rate INTEGER
);
```
- **역할**: 사용자의 상세 정보 및 멘토 관련 설정
- **특징**: 고향/정착희망지역으로 귀향자 특성 반영

#### `social_accounts` - 소셜 로그인 연동
```sql
CREATE TABLE social_accounts (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  provider VARCHAR(6) NOT NULL CONSTRAINT ck_social_accounts_provider CHECK (provider IN ('google','kakao','naver','apple')),
  provider_uid VARCHAR(255) NOT NULL,
  CONSTRAINT uq_social_accounts_provider_uid UNIQUE (provider, provider_uid)
);
CREATE INDEX ix_social_accounts_user_id ON social_accounts (user_id);
```
- **역할**: 구글, 카카오, 네이버와 같은 소셜 로그인 지원

### 🔹 3. 미션 시스템 (Gamification)

#### `missions` - 미션 정의
```sql
CREATE TABLE missions (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  code VARCHAR(64) CONSTRAINT uq_missions_code UNIQUE,
  title VARCHAR(200),
  mission_type VARCHAR(5) NOT NULL CONSTRAINT ck_missions_mission_type CHECK (mission_type IN ('탐색형','사회유대형','커리어형')),
  difficulty SMALLINT DEFAULT 1,
  expected_minutes SMALLINT,
  tags JSONB,                    -- ["경로당","마을회관","문화체험"] 등
  description TEXT,
  thumbnail_image VARCHAR(500)
);
```
- **특징**: 3가지 미션 유형으로 다양한 참여 방식 제공

#### `mission_parts` - 미션 세부 단계
```sql
CREATE TABLE mission_parts (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  mission_id BIGINT NOT NULL REFERENCES missions(id),
  step_no SMALLINT NOT NULL,
  instruction TEXT,              -- 세부 단계 안내
  checklist JSONB,               -- 체크리스트(선택)
  CONSTRAINT uq_mission_parts_mission_step UNIQUE (mission_id, step_no)
);
```

#### `mission_assignments` - 사용자별 미션 배정
```sql
CREATE TABLE mission_assignments (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  mission_id BIGINT NOT NULL REFERENCES missions(id),
  assigned_at TIMESTAMPTZ DEFAULT now(),
  due_date DATE,
  status VARCHAR(11) DEFAULT 'assigned' CONSTRAINT ck_mission_assignments_status CHECK (status IN ('assigned','in_progress','completed','skipped','canceled')),
  context JSONB                  -- 추천 근거(장소/문화/이전행동 등)
);
CREATE INDEX ix_mission_assignments_user_status ON mission_assignments (user_id, status);
CREATE INDEX ix_mission_assignments_mission_id ON mission_assignments (mission_id);
```

#### `mission_progress` - 미션 진행 상황
```sql
CREATE TABLE mission_progress (
  assignment_id BIGINT PRIMARY KEY REFERENCES mission_assignments(id),
  progress_pct SMALLINT DEFAULT 0,
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,
  feedback TEXT
);
```

#### `mission_part_progress` - 세부 단계별 진행 상황
```sql
CREATE TABLE mission_part_progress (
  assignment_id BIGINT REFERENCES mission_assignments(id),
  part_id BIGINT REFERENCES mission_parts(id),
  done BOOLEAN DEFAULT false,
  memo TEXT,
  done_at TIMESTAMPTZ,
  PRIMARY KEY (assignment_id, part_id)
);
```

### 🔹 4. 지역 데이터 (Location & Culture)

#### `location_categories` - 장소 분류 체계
```sql
CREATE TABLE location_categories (
  id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  main VARCHAR(50),              -- 예: '식음료','의료','공공시설'
  sub VARCHAR(80),               -- 예: '맛집','카페','병원/의원','경로당','마을회관'
  CONSTRAINT uq_location_categories_main_sub UNIQUE (main, sub)
);
```

#### `locations` - 지역 장소 정보
```sql
CREATE TABLE locations (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  category_id INTEGER NOT NULL REFERENCES location_categories(id),
  address VARCHAR(300) NOT NULL,
  phone VARCHAR(40),
  geom geometry(Point, 4326) NOT NULL,   -- POINT(경도 위도)
  extra JSONB                            -- 원시칼럼 보관(출처/링크 등)
);
CREATE INDEX ix_locations_geom ON locations USING gist (geom);
CREATE INDEX ix_locations_category_id ON locations (category_id);
CREATE INDEX ix_locations_name ON locations (name);
```
- **특징**: PostGIS `geometry(Point, 4326)` + GiST 인덱스로 반경 검색 등 지도 기반 검색 지원 (좌표 순서는 `POINT(경도 위도)`)

#### `location_hours` - 운영시간 정보
```sql
CREATE TABLE location_hours (
  location_id BIGINT REFERENCES locations(id),
  weekday SMALLINT,              -- 0(일)~6(토)
  open_time TIME,
  close_time TIME,
  is_24h BOOLEAN DEFAULT false,
  PRIMARY KEY (location_id, weekday)
);
```

#### `location_tags` - 장소 태그 시스템
```sql
CREATE TABLE location_tags (

  PRIMARY KEY (location_id, tag)
);
CREATE INDEX ix_location_tags_tag ON location_tags (tag);
```

#### `culture` - 문화 자산 데이터
```sql
CREATE TABLE culture (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  category VARCHAR(3) NOT NULL CONSTRAINT ck_culture_category CHECK (category IN ('인물','전설','유래','역사','문화재')),
  title VARCHAR(300) NOT NULL,

  haman_url VARCHAR(500),
```

### 🔹 5. 커뮤니티 시스템

#### `board_posts` - 통합 게시판 (자유·의뢰·멘토)
```sql
CREATE TABLE board_posts (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  author_user_id BIGINT NOT NULL REFERENCES users(id),
  board_type VARCHAR(7) NOT NULL CONSTRAINT ck_board_posts_board_type CHECK (board_type IN ('free','request','mentor')),
  category VARCHAR(30) NOT NULL,
  title VARCHAR(200) NOT NULL,
  content TEXT NOT NULL,
  images JSONB,                          -- 첨부 이미지 URL 배열
  attributes JSONB,                      -- 게시판별 추가 정보 (예산, 시간당 요금 등)
  match_status VARCHAR(8) CONSTRAINT ck_board_posts_match_status CHECK (match_status IN ('open','matched','closed','canceled')),  -- 의뢰·멘토 글 진행 상태 (자유게시판은 NULL)
  views_count INTEGER DEFAULT 0,
  likes_count INTEGER DEFAULT 0,
  comments_count INTEGER DEFAULT 0,
  status VARCHAR(7) DEFAULT 'active' CONSTRAINT ck_board_posts_status CHECK (status IN ('active','hidden','deleted')),
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
CREATE TRIGGER trg_board_posts_updated_at BEFORE UPDATE ON board_posts
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
CREATE INDEX ix_board_posts_board_category_created ON board_posts (board_type, category, created_at);
CREATE INDEX ix_board_posts_author_user_id ON board_posts (author_user_id);
CREATE INDEX ix_board_posts_board_match_status ON board_posts (board_type, match_status);
```
- **게시판 구분**: `board_type` = free(자유) · request(의뢰) · mentor(멘토). 의뢰·멘토 글의 진행 상태는 `match_status`, 수락·신청 기록은 `matches`
- **category (앱 화면의 키와 동일)**: free = daily·food·memory·nature·hobby·other / request = repair·agriculture·it·cleaning·installation / mentor = technical·agriculture·lifestyle·business·education·seeking·offering
- **attributes (게시판별 추가 정보)**: request = budget·location·deadline·required_skills / mentor = experience·hourly_rate·location·skills·preferred_method

#### `board_comments` - 댓글 시스템

```sql
  created_at TIMESTAMPTZ DEFAULT now()

CREATE INDEX ix_board_comments_post_created ON board_comments (post_id, created_at);
```

#### `likes` - 좋아요 시스템

```sql
CREATE TABLE likes (
```

## 🔗 주요 관계도

### 사용자 중심 관계
```
users (1) ←→ (1) user_profiles
users (1) ←→ (N) user_skills
users (1) ←→ (N) user_badges
users (1) ←→ (N) mission_assignments
```

### 미션 시스템 관계
```
missions (1) ←→ (N) mission_parts
missions (1) ←→ (N) mission_assignments
mission_assignments (1) ←→ (1) mission_progress
mission_assignments (1) ←→ (N) mission_part_progress
```

### 지역 데이터 관계
```
location_categories (1) ←→ (N) locations
locations (1) ←→ (N) location_hours
locations (1) ←→ (N) location_tags
```

### 커뮤니티 관계
```
board_posts (1) ←→ (N) board_comments
users (1) ←→ (N) likes
board_posts (1) ←→ (N) matches
```

### 1. **단일 PostgreSQL 아키텍처**
- **PostgreSQL**: 구조화된 데이터의 마스터 저장소
- **pgvector**: `rag_documents.embedding` 으로 의미 기반 벡터 검색 (별도 벡터 DB 불필요)
- **PostGIS**: 위치 데이터와 공간 검색

### 2. **공간 데이터 지원**
- PostGIS GiST 공간 인덱스 활용 (`ST_DWithin` 반경 검색 등)
- WGS84 좌표계(SRID 4326) 사용, 좌표 순서는 `POINT(경도 위도)`
- 지도 기반 검색 및 위치 서비스 지원

### 3. **유연한 확장성**
- JSONB 필드 활용으로 스키마 변경 최소화
- CHECK 제약으로 허용 값 제한 (ENUM 대신 사용해 값 추가/삭제가 쉬움)
- 모듈화된 테이블 구조로 기능별 독립성

### 4. **성능 최적화**
- 적절한 인덱스 설계
- 외래키 제약조건으로 데이터 무결성
- 복합 인덱스로 쿼리 성능 향상
